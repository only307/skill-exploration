# markdown笔记整理

**markdown笔记整理 · v1.2**

把课堂草稿、已有 Markdown 笔记及配套图片、文字、PPT、Word、PDF，或单独提供的这些素材整理成便于学习的正式笔记或便于复习的大纲笔记。支持多份素材合并与后续补充，优先保护原始文件和已有知识。

本项目提供执行规则，不附带模型、识别引擎或文件操作工具。实际支持的格式和文件交付方式取决于使用它的 AI／Agent 环境。

## 选择哪种笔记

| 类型 | 适合做什么 | 内容特点 |
| --- | --- | --- |
| 正式笔记 | 系统学习、理解和查阅 | 较完整的概念、原理、关系、必要例题及解题步骤 |
| 大纲笔记 | 快速复习、检查知识框架 | 知识点、分类、核心公式、条件及关键联系，避免长篇教学 |
| 两者都生成 | 详细学习与快速回顾配合使用 | 分别生成或更新两个独立文件 |

**每次任务先确定这三个选项中的一个。** 已明确选择时无需重复回答；没有选择时 Agent 应先询问，不能根据文件名自动决定。

## 三种文件相互独立

同一主题使用以下规范新文件名：

```text
概率论笔记-草稿.md
概率论笔记-正式.md
概率论笔记-大纲.md
```

- 已明确类型的草稿、正式和大纲笔记，名称不规范时都须先安全改为统一格式；纯改名完整字节不变，不能覆盖同名文件。保护的是正文与知识，不是旧文件名。
- 正式笔记和大纲笔记共享来源，各自增量更新，不能相互覆盖。
- 仅选择一种类型时不会为了凑齐文件而创建另一种或空草稿。
- 旧版文件一经明确类型，必须先规范名称，再整理或更新；不能继续沿用 `概率论笔记.md` 等旧名。
- 正式笔记可作为大纲来源，大纲可作为正式笔记的结构参考；非本次输出类型的笔记若类型已明确，也会只规范文件名，正文仍不修改。普通素材和类型未明的 Markdown 不擅自改名。

例如 `概率论草稿笔记.md` → `概率论笔记-草稿.md`；你确认 `概率论笔记.md` 是正式笔记后，它必须改为 `概率论笔记-正式.md`，再在新名称下更新。已识别的大纲旧名同理。输入类型未明时先问，不靠篇幅判断；规范名已被另一文件占用时暂停并请你决定，不覆盖、不合并或随意加后缀。你明确禁止改名时，该文件的操作暂停。

## 四种输入分支

输出类型选择与输入分支是两层独立判断，分支 A/B/C/D 不代表输出选项。

| 分支 | 你提供什么 | Agent 如何处理 |
| --- | --- | --- |
| A | 文件名含“草稿”或你明确说明是草稿的 Markdown，可附多份素材 | 完成内容范围与保存位置选择后先安全规范草稿名，再整理草稿并合并素材；生成或增量更新所选笔记，草稿正文不改 |
| B | 非草稿笔记＋图片、文字或文档 | 先规范所有已识别笔记名称，再对比已有知识补充新细节；所选类型与输入不同则生成／更新独立目标 |
| C | 只有非草稿笔记，无补充素材 | 先规范已识别笔记名称；正式模式排版校对，大纲模式提炼／完善结构，不无依据扩写知识 |
| D | 仅有 PPT、照片、PDF、Word 或知识文字，没有 Markdown 来源或指定旧目标 | 先确认保存位置，根据选择总结生成正式、大纲或两者；对应旧目标已存在则先规范名称、读全再增量更新 |

从零开始只提供素材时走 D 分支，不必补交 Markdown，也不会创建空草稿。如果你明确要求更新既有笔记，则走 B 分支，须提供可读取的已有目标文件或明确路径；目标无法读取时不会用 D 分支的新文件冒充更新。多份素材都会纳入处理；若存在矛盾，会保留来源区别并提示复核，而非直接合成一个确定结论。

## 基本使用

1. 在支持 Skill 的 Agent 中加载本目录的 [SKILL.md](SKILL.md)。
2. 上传笔记及相关素材，或提供当前环境真实可访问的文件路径。
3. 明确选择“仅正式”“仅大纲”或“两者”，必要时说明主题与保存目录。
4. 当理工科素材含历史或时事知识时，分别决定实际存在类别的保留范围；保存地址不明确时先选定真实目录。
5. 查看最终规范文件路径、增量位置和临时文件清理结果。

可以这样提出请求：

> 使用 markdown笔记整理，将我上传的“概率论草稿笔记.md”和三张课堂图片整理为正式笔记和大纲笔记，保存到草稿所在目录。

> 只更新大纲笔记。以“机器学习笔记-正式.md”和这份 PPT 为来源，补充“机器学习笔记-大纲.md”；正式笔记可规范文件名，但正文不要修改。

> 仅整理“计算机网络笔记-正式.md”的格式并校对，保留全部已有内容。若需补充纠正说明，请在对话中告诉我位置和原因。

> 沿用本次选择的两种笔记，把这份 PDF 增量合并到之前明确的两个目标。已出现的知识不要重复追加。

> 我只提供这份“线性代数”PPT 和两张课堂照片，请总结生成正式笔记和大纲笔记，主题为线性代数；正式笔记保留重要说明和结构，大纲由你归纳，不要整份照搬素材。

## 保存位置先确认

Agent 按顺序使用：你明确指定的目录；更新已有目标时唯一、稳定、可写的原目录；新建时全部相关本地来源共同所在的唯一、稳定、可写目录。保存路径或目录权限不清楚、素材跨多个目录、只有附件／缓存路径、默认目录与素材目录冲突时，必须在改名或写入前向你确认，不能静默将最终文件留在任务目录或附件缓存。

提问须展示经过现场确认的**真实绝对路径**，分别列出默认地址、推荐地址（附理由）以及供你填写的自定义绝对地址。以下仅示意提问格式；实际执行时 Agent 必须换成当时已核实的路径，不能照抄示意路径：

> 默认地址：`C:\Users\student\Desktop\课程笔记`（假设这是当前环境真实的默认路径）  
> 推荐地址：`D:\学习资料\概率论`（假设素材和已有笔记都在这里，方便连续更新）  
> 自定义地址：请提供你希望使用的其他绝对路径。

默认和推荐可以相同，但要分别标明。用户未回答地址歧义时不创建最终笔记。只能生成下载文件的平台会先说明本地保存限制，交付规范文件名及真实生成位置／有效链接，说明原本地文件未修改，不能将平台内部位置冒充你指定的目录。

## 理工科素材中的历史与时事

整理数学、计算机、工程、医学等理工科笔记时，如果素材确实含发展史、发现过程、历史人物等历史知识，或近期新闻、政策／行业动态、发布事件等时事知识，Agent 会在**改名、建目录和写最终文件之前**分别询问实际存在类别：历史保留／不保留，时事保留／不保留。只有一类就只问一类；日期、版本号或姓名本身不自动触发。当前请求已分别说明则沿用，不重复询问；无法可靠分类时先让你确认。

两类都存在时可以只保留历史、只保留时事、两类都保留或两类都不保留。选择“不保留”只影响这次新建和新增内容，**不会删除旧笔记里的同类知识**。背景与公式、条件、定义或实验结论混在一起时，核心技术内容仍应保留；无法安全分离会请你确认。保留时事时写明素材原有时间与来源，不暗示它在今天仍有效；不会自动上网补新闻。非理工科笔记不触发这一强制选择。

## 安装或接入

本版本的四个文档可以整体分享：

```text
Markdown-Note-Organizer/
└── v1.2/
    ├── SKILL.md
    ├── README.md
    ├── AGENT_REQUIREMENTS.md
    └── CHANGELOG.md
```

若平台支持目录式技能，将 `v1.2` 内这四个文件放到该平台规定的技能目录中，保证 `SKILL.md` 位于技能根目录。若平台要求小写标识同名目录，可用 `markdown-note-organizer` 作为安装目录名，保持四个文件相邻；项目发布路径仍为上面的版本目录。

技能名称为 **markdown笔记整理**，项目目录名为 `Markdown-Note-Organizer`；元信息中的机器标识为 `markdown-note-organizer`，以满足小写连字符命名要求。不同平台如何发现、启用或显式调用技能，请以该平台实际文档为准；不能假定它们都支持相同命令。仅把项目下载到任意目录不代表已经被 Agent 自动加载。

不支持技能安装但可以使用自定义指令的平台，可将 `SKILL.md` 作为执行规则提供，并按需附上能力说明；这不会自动增加读写文件或识别文档的权限。当前版本没有安装脚本，也不要求创建仓库或联网。

## 文件操作与下载降级

有本地读写工具时，Agent 在内容范围与保存位置确认后，先安全规范全部已识别笔记名称，再创建或更新所选目标，写后核对结果。已有笔记须完整读取；两个目标分别检查，不能互相覆盖。

**如果本地无法写入，但能完整读取来源和旧目标，且环境支持生成文件，自动改为提供可下载的完整 `.md` 文件。** 名称与内容规则相同；选择两者时提供两个文件，并说明哪些本地原文件未修改，需要你自行保存或替换。下载结果不会自动同步回本地。若只作参考的已识别笔记需要改名但无法本地重命名，可额外提供规范名、字节不变的副本；需要更新的目标只提供规范名的完整更新版，避免两个同名下载文件互相覆盖，并说明本地旧名仍存在。

文件链接必须对应真实生成结果。旧目标读不全时不能用只有新增段落的文件冒充完整更新版；既不能本地写入也不能生成文件时，只能明确说明未完成交付。图片资源无法随输出提供时，会说明引用限制。

工作过程中产生的转换、OCR、预览、候选及验证文件应放在本次任务专用临时目录。完成或提前停止时只清理本次创建的具体中间文件与空临时目录；不会删除用户素材、原始／已改名笔记或最终交付文件。清理失败时会列出真实路径和原因。

## 正式与大纲的整理方式

正式笔记应保留重点内容、必要原句、重要说明和有助理解的写法与布局，同时对冗余、重复或无关信息总结、合并或省略。不能把整份 PPT 或草稿逐字转为 Markdown，只换排版就交付；也不能为了改写而改变准确的定义或公式。

大纲笔记必须由模型理解并总结，禁止直接照搬来源段落或列表。术语、公式和定理名称等必要准确表达可以保留原样。两者同时生成时，分别满足上述要求，不把正式笔记复制一份当大纲。

这些筛选规则适用于新笔记和新增内容，不能用于删掉已有目标笔记中的知识；仅做格式校对也不需要强行重写原文。

## 内容与格式保护

- 不删旧知识、不精简掉旧例子、不改草稿正文；三类已识别笔记的不规范文件名都要改规范，纯改名不改变完整字节。允许不改变含义的排版调整与知识增量添加。
- 发现明确错误，保留原文并追加有依据的纠正说明；不确定时保留原文并标记疑义。
- 已有英文对照保留；只裁剪新生成／新增文字中冗余的英文对照。缩写、英文例句、论文名、公式、代码和来源标注保留。
- 常见缩写不强制展开；局部简写在意义唯一时补上全称，不凭猜测改写。
- 正式笔记中的学术与专业术语在整篇首次出现时加粗，后续再次出现不加专门标识；增量补充也先检查旧全文。大纲保留原有首次加粗规则，代码和公式不插入格式标记。
- 正式笔记的明确解题方法使用整块黄色荧光；编号、关键词或概念分类本身不会触发。大纲不新加黄色荧光。
- 不确定的修正建议可整段标绿并注明待复核。识别含糊的内容标为 `【图片识别，存疑】` 或 `【文档识别，存疑】`。
- 必要的模型构造示例会与来源例子区分，仍需你复核；不会作为已核实的材料事实。
- 原有 TODO、待补充和疑义保留。大纲不会未经反馈判断你已经掌握哪些内容。
- 文件内不写更新日志或本次操作说明；新增位置及实质内容变化在对话结束时单独报告。

## 重要限制

完整合并 PDF／Word／PPT 需要对应解析能力，关键图片需要图像识别；扩展名相同也不保证扫描、加密、旧版或损坏文件可读取。不能识别的材料会明确报告，不假装已全部处理。

黄色和绿色采用带块级样式的 HTML `mark`。阅读器可能过滤 HTML、忽略样式或无法在块内渲染数学内容，**没有跨阅读器兼容保证**。支持预览时应在实际阅读器中检查；不能预览时会明确说明未验证。需要其他展示方式时，可向 Agent 说明你的阅读器限制。

已有大纲不能靠删除旧知识来变短；如果保留与精简冲突，会请求你决定。目标路径、文件类型、素材归属或理工科背景类别不明确时也会先询问，避免改错文件或误删有用信息。

本版本完成静态规则与文件结构检查，未实际执行用户笔记整理，也未验证 OCR、文档解析、不同阅读器渲染或平台安装效果。能力边界见 [AGENT_REQUIREMENTS.md](AGENT_REQUIREMENTS.md)，版本记录见 [CHANGELOG.md](CHANGELOG.md)。
